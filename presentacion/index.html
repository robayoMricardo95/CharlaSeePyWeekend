1 · El LLM básicoNotebook 01 · Partes 1 y 2

Un LLM predice el siguiente pedazo de texto

Lo que es

Un programa que completa texto a partir de lo que leyó al entrenarse.

Vive en un servidor del proveedor y se le habla por internet, con una key.

Se cobra por token (≈ 4 caracteres): entrada y salida, por separado.

Lo que no puede

"¿Qué fecha es hoy?" → "10 de junio de 2024". No tiene reloj.

"¿Cuánto se pagó en hospitalización en 2009?" → pide que le pasemos los datos. La base dice 245 512 790.

Para responder sobre nuestra base necesita contexto y una herramienta.

En el notebook: ejemplo 2 (rol system), ejemplo 3 (temperatura 0 repite, 1 varía), ejemplo 4 (max_tokens=15 corta: finish_reason = length). Después la Parte 2: fecha y datos.

El dato y el diccionario

La tabla sabana: una fila por reclamo, 656 147 reclamos de 2008 y 2009. Un caso: una afiliada de Oregón, 69 años, 4 reclamos en 2009; la aseguradora pagó 3 160 y la atención costó 4 278.

Escenario 1 · solo los nombres de las columnas

WHERE ambito = 'hospitalización'

Resultado: None. El SQL corre… y responde mal.

Escenario 2 · con el diccionario

WHERE ambito = 'Hospitalario'

Resultado: 245 512 790 ✓

El agente no falla por el modelo: falla por no saber qué significa cada columna.

El diccionario: 25 columnas, 7 trampas del dato, 10 consultas de ejemplo (12 053 caracteres). Después, los dos tipos de pregunta: un solo número (ambulatorio 2009: 94 184 290) y agrupada por sexo (Femenino 54 452 370, Masculino 39 731 920). Las dos coinciden con la base.
2 · LangChainNotebook 02 · Parte 3 · La caché

El diccionario cuesta. La caché lo abarata.

EscenarioTokens de entradaDe cachéCon cachéSin cachéAhorro
1. Sin diccionario1610USD 0,0006580,0006580 %
2. Con diccionario3 6093 584USD 0,0020900,00746672,0 %
3. Con diccionario, en caché3 6103 584USD 0,0021240,00750071,7 %
  • El proveedor guarda el inicio del prompt (instrucciones + diccionario). Si la siguiente llamada empieza igual, esa parte cuesta 0,50 en vez de 2,00.
  • La pregunta va al final: puede cambiar sin romper la caché. Un cambio antes de ella, y se pierde.
En Foundry la caché es automática (prefijo idéntico de más de 1 024 tokens). El tope de ahorro es 75 % de la entrada; la salida nunca se descuenta. Dura de minutos a ~1 hora sin uso.
2 · LangChainNotebook 02 · Parte 4 · La tool

El LLM escribe, nuestro código ejecuta

El modelo pidetool_calls[0] con el SQL
→
Nuestro código ejecuta@tool ejecutar_sql · solo lectura
→
El modelo redactacon el resultado

cadena_completa = (
    RunnablePassthrough.assign(respuesta_sql=plantilla | foundry)          # 1. escribe el SQL
    | RunnablePassthrough.assign(sql=...)                                   # 2. lo limpia
    | RunnablePassthrough.assign(filas=lambda d: ejecutar_sql.invoke(...))  # 3. la tool lo ejecuta
    | RunnablePassthrough.assign(respuesta_final=plantilla_redaccion | foundry)  # 4. redacta
)

La forma rápida: todo en una sola llamada. Redactar cuesta casi nada (114 tokens, USD 0,000476): el peso está en el diccionario.

Pasos 1 a 6 en el notebook: definir la tool (el docstring es lo que lee el modelo), ver su ficha, ejecutarla a mano, bind_tools, el modelo pide, nuestro código ejecuta, el modelo redacta. "Lo que recibe el modelo": [SystemMessage(sistema), HumanMessage(pregunta)].
